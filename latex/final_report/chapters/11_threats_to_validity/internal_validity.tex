\section{Internal Validity}
\label{sec:internal_validity}
Internal validity concerns whether the experimental setup accurately measures what it intends to measure without interference from confounding variables.
\begin{itemize}
    \item \textbf{Implementation Bugs:} As a research prototype, there is a risk of undiscovered implementation bugs within the Rust microservices or Python workload generator that could skew telemetry data. The inactive \texttt{blob\_fill\_target} parameter is a clear example of such a defect.
    \item \textbf{Configuration Errors:} The complexity of orchestrating multiple Docker containers means that subtle misconfigurations in environment variables or TOML templates could lead to inconsistent runs. The error that caused Stage 2 adaptive batching to behave like fixed batching demonstrates this vulnerability.
    \item \textbf{Benchmark Harness Interference:} The telemetry collection itself, particularly file I/O operations, introduces a small degree of overhead that may marginally impact the measured latency at extreme throughputs.
    \item \textbf{Tail-Batch Distortion:} The lack of an end-of-test mempool flush caused the final batch in finite test runs to wait for the entire timeout duration, distorting the average queue wait time and inflating simple average gas costs for empty tail batches.
\end{itemize}
