\subsection{RQ2: Impact of Sequencer Scheduling Policies}
Implementing the prototype revealed several practical engineering challenges regarding transaction queueing. Relying on the local Hardhat RPC for rapid, automated submissions highlighted the volatility of L1 gas estimation and the necessity of robust retry mechanisms (implemented via the Submitter's Saga pattern). Furthermore, ensuring state consistency between the Sequencer's pessimistic cache and the Executor's canonical state root required strict message ordering via gRPC. Different sequencer scheduling policies (such as strict FCFS versus size-based limits) directly govern this queueing behavior and determine how fairly and quickly user transactions achieve soft finality under network congestion.
