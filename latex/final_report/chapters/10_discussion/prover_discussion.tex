\subsection{RQ1: Impact of Batch Size on Cost and Latency}
The empirical data explicitly answers the trade-off regarding batch size. While large batch sizes drastically reduce the amortized per-transaction L1 gas cost and the fixed prover setup cost, they directly inflate proof generation latency and transaction queueing times. In scenarios where real cryptographic proof generation dominates the execution time (masking all other systems-level bottlenecks), increasing the batch size distributes the massive fixed setup time across more transactions, but risks causing severe backpressure on the L2 state if the throughput exceeds the prover's linear cycle capacity.
