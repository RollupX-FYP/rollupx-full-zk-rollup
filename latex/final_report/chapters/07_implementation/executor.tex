\section{Executor}
\label{sec:executor}
The Executor serves as the host-side state transition and proving coordinator.

\begin{itemize}
    \item \textbf{Language:} Rust (requires \texttt{nightly-2024-08-01} toolchain due to \texttt{risc0} dependencies).
    \item \textbf{Execution Role (State Transition Function):} It processes a \texttt{publish\_batch} request via gRPC. It parses and normalizes transactions, and executes the state transition function (STF) using a \texttt{SimpleTransactionEngine}. The STF strictly verifies account balances and strict nonce ordering. If a transaction nonce is out of order, the STF rejects the transaction, preventing subsequent execution for that account.
    \item \textbf{State Manager:} State updates are persisted and tracked using a Sparse Merkle Tree backed by a \texttt{RocksDbStateManager}. This structure generates the exact Merkle proofs required for the zero-knowledge circuits.
    \item \textbf{Prover Integration:} After execution, it builds an \texttt{ExecutionTraceV1} and invokes the configured prover backend to generate proof artifacts. 
    \item \textbf{Output:} It emits an enriched batch payload (containing the DA commitment and proof) back to the Submitter stream and logs execution metrics.
    \item \textbf{Limitations:} The executor is a simplified state-transition engine tailored for transfer-style workloads and Merkle state updates (transfer-centric research logic). It is explicitly not a full EVM or zkEVM. 
\end{itemize}
